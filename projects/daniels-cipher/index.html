Analysis of a Card-Shuffle Stream Cipher

Cycle structure, rotation variants and weak keys in the Daniels' Cipher, a new hand cipher that runs on two decks of playing cards and had not been analyzed before.

The problem

Hand ciphers have to be simple enough to run with physical objects and still hold up against an adversary with real computing power. The best-known modern example, Schneier's Solitaire, was later shown to have a measurable output bias, and most analysis of hand ciphers has been statistical. Dr. Daniels designed a new card-shuffle stream cipher, built on two operations (a Count Cut and a Search Cut) applied across a driver deck and a search deck, with a keystream that depends only on the key and IV.

My approach

Instead of sampling the output, I shrank the cipher until its entire state space fit in memory, so its cycles, keys and weak keys become facts rather than estimates.

  • Proved the round transition is one-to-one on the (n!)² state space, so the space splits cleanly into disjoint cycles with no dead ends. This separates it from Solitaire, whose update is not reversible.
  • Listed every cycle for deck sizes 4, 6 and 8 at four discard-rotation values, including cycles no key starts on, and verified each case by requiring the cycle lengths to sum exactly to (n!)².
  • Indexed permutation states with Lehmer codes into a bitset (one bit per state), so the deck-8 case ran on a machine with under 2 GB of usable memory.
  • Measured how the key schedule spreads keys across cycles, and tested keystream output for uniformity and pair correlation with chi-square tests.
  • Introduced a common unit, keystream bits before repetition, so the deck-size variants can be compared with each other and with published stream ciphers.

Findings

  • The discard rotation, a parameter with no obvious cryptographic role, changes the cycle structure dramatically: at deck size 8 the share of keys on the largest cycle ranges from 44.83% to 78.40%.
  • Keys land on cycles in proportion to cycle length, with no measurable bias.
  • Short-cycle weak keys exist and are identified exhaustively at the reduced deck sizes.

Scope, stated plainly: this is an exploration of the cipher's structure, not a security proof. Cycle length bounds how long the keystream can run before repeating; it does not by itself show the cipher is secure.

Tools I built

  • A C implementation of the cipher with cycle detection over Lehmer-encoded states in a compact bitset (cbitset).
  • A Lehmer code encoder and decoder for permutation indexing.
  • Statistical tests: single-output chi-square uniformity, consecutive-pair correlation and a lag-n difference filter for linear dependence.
  • A parser that turns run logs into cycle-length distributions and flags weak keys.

The research code lives in a private working repository. The paper includes the pseudocode and every table behind the results.
