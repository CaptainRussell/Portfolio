Analysis of a Card-Shuffle Stream Cipher

The first study of a new cipher you can run by hand with playing cards: how long it runs before repeating, and which keys are weak.

  • Program: M.S. Cybersecurity, Iowa State University
  • Major professor: Dr. Thomas E. Daniels
  • Year: 2026
  • Role: Sole author

The idea

Dr. Thomas Daniels designed a new cipher that a person can run with two decks of cards and no computer. Shuffling the decks in a set way turns a secret key into a stream of letters that hides a message. No one had studied it before.

A stream like this eventually starts repeating, and repetition is a weakness. The question was: how long does it run before it repeats, and are some keys much worse than others?

What I did

  1. Shrank the decks. With 4, 6 or 8 cards per deck, every possible arrangement of the decks fits in a computer's memory.
  2. Followed every arrangement. I wrote a C program that tracked all of them, at deck size 8 more than 1.6 billion, on an ordinary laptop.
  3. Tested every key. All 16.7 million keys at deck size 8, so the results are exact counts, not estimates.

What I found

  • The cipher never gets stuck. Every arrangement sits on a closed loop that leads back to itself, so the length of a key's loop is how long its stream can run before starting over.
  • One small setting, the rotation value, changes the results a lot: depending on it, between 45% and 78% of keys land on the longest loop.
  • Most keys are fine, but a few weak keys repeat very quickly. The study lists them.

Limits: this maps how the cipher behaves. It does not prove the cipher is secure.

The proofs, the method, the pseudocode and every table are in the paper.
